# 業者表單與真實客人高頻問題缺口分析

分析依據：[JunZan AI 真實 LINE 客人對話語料分析](REAL_GUEST_CONVERSATION_STATISTICS.md)。統計涵蓋 4,172 個 LINE CSV、2,692 組有效對話及 22,025 則客人訊息；問題分類採多標籤計數，同一訊息可能同時落入多類。

本分析只對照目前既有的業者 onboarding 與業者後台。現況包含房況管理、房型與四類基本價格、特定日期價格、包棟方案、常見問題、包棟設備、自訂回覆，以及可輸入狀態、適用範圍、費用、預約、條件、限制、使用時段與適用期間的正式資料表單。本文件只指出資料收集缺口，不修改表單或產品行為。

## 建議新增的固定欄位

以下欄位屬長期、跨案例且直接影響高頻回答的正式資料；應由業者明確填寫，不應由 AI 猜測。

- 房型與包棟：基本入住人數、最大入住人數、最多可加人數、是否可加床、加床型態。
- 年齡規則：兒童與嬰幼兒的年齡區間、是否計入入住人數、是否收費。
- 價格構成：加人費、加床費、兒童費、固定清潔費及各費用單位；總價仍由正式價格與住宿晚數計算，不另填一個容易過期的「總價」。
- 訂房條件：訂金採固定金額或比例、付款期限、尾款支付時點、可用付款方式、訂房成立條件。
- 房況政策：可預訂窗口、最少入住晚數、特殊期間連住限制；逐日可售狀態仍以房況日曆為準。
- 入住流程：最早入住、最晚抵達、退房時間、自助入住與否、行李寄放時段；房門密碼不納入固定公開欄位。
- 導航：正式地址、Google Maps 網址、停車入口或抵達辨識說明。
- 規則適用範圍：每項設施或規則明確標記為單訂房間、特定房型、包棟方案或整間旅宿。

## 不適合放進固定表單的低頻項目

這些內容容易變動、具有個案性、含敏感資料，或應由另一個正式資料來源負責；不應為了少數問法擴大固定表單。

- 附近景點、商店及餐廳推薦（附近景點／商店 110）：使用業者核准的自訂回覆或可維護的正式推薦資料，避免把可能過期的營業資訊寫死。
- 早餐店或外部供應商的電話、地址與優惠：屬第三方資訊，應由核准資料或自訂回覆管理，不保存客人或聯絡人的個資。
- 發票／收據 39、訂單確認 128、付款是否入帳：屬訂單或財務流程；固定表單只保存公開政策，不保存客人的姓名、電話、帳號末碼或交易明細。
- 取消、改期、颱風、損壞、退款與爭議的個案判斷：固定表單只保存核准政策；實際案件交由正式訂單資料或人工處理。
- 房門、大門、戲水池密碼及一次性入住資訊：不得放進公開固定回答、自訂回覆或語料報告，應由受控入住流程提供。
- 床墊供應商、臨時合作邀約、廣告與推銷訊息：與旅宿核心回答無關，通常應忽略或人工處理。
- 單次臨時公告、特定日期設施停用或尚未公告價格：使用有生效期間的自訂回覆；正式房況與價格仍以各自權威資料為準。

最重要的缺口不是完全沒有資料入口，而是高頻關鍵資料仍依賴自由文字或手動 JSON：加人／兒童的容量與費用、可計算總價的附加費、訂金與尾款條件，以及烤肉、停車、戲水池、寵物、KTV 的時段／費用／預約／適用範圍。若未改為明確固定欄位與勾選後展開欄位，業者很容易只填「有／沒有」，使 JunZan AI 無法以正式資料完整回答真實高頻追問。
