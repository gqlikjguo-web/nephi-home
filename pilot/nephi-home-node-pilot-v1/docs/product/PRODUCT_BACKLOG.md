# JunZan AI 產品待辦池

本文件只記錄產品待辦；實作細節於排程後另行確認。

## P0／V1.x

### 1. LINE 串接精靈

- 解決的痛點：業者目前需要接觸 Render，且 LINE 憑證、Webhook 與 Reply API 缺少一站式驗證。
- 優先級：P0
- 階段：V1.x
- 狀態：未排程
- 完成標準：業者可在 JunZan AI 安全頁面輸入 Channel ID、Channel Secret、Access Token，自動取得專屬 Webhook，並看到 Secret、Token、Webhook、Reply API 的明確驗證結果。

### 2. LINE 設定防呆

- 解決的痛點：缺值、名稱錯誤或貼錯 Channel 可能造成跨業者綁定與正式鏈路失敗。
- 優先級：P0
- 階段：V1.x
- 狀態：未排程
- 完成標準：系統會阻擋 Secret 綁錯業者、缺值與錯誤 Channel，並以 Service 實際狀態驗證設定，不只依賴 render.yaml 或 Blueprint 宣告。

### 3. 正式環境證據規則

- 解決的痛點：程式宣告容易被誤報為正式環境已設定，導致錯誤決策。
- 優先級：P0
- 階段：V1.x
- 狀態：未排程
- 完成標準：所有正式環境回報均附實際證據，並明確區分「程式宣告」與「正式環境已設定」，不得以推測宣稱存在。

### 4. AI 回覆安全層盤點與補強

- 解決的痛點：低信心、高風險、缺欄位、過期上下文與未知問題可能產生不安全或猜測式回覆。
- 優先級：P0
- 階段：V1.x
- 狀態：未排程
- 完成標準：白名單資料與固定模板、低信心及高風險轉真人、缺欄位補問、上下文清理、判斷與回覆紀錄、未知問題安全退路皆有自動測試證明。

### 5. 每家業者 10～20 組客製化自動回覆

- 解決的痛點：不同業者無法安全維護自己的常見問答、處理方式與啟用狀態。
- 優先級：P0
- 階段：V1.x
- 狀態：未排程
- 完成標準：每個 propertyId 可獨立設定 10～20 組標準意圖及答案，並支援自動回答、補問、轉真人、暫停與未設定狀態。

### 6. 新業者導入完成檢查清單

- 解決的痛點：導入進度與缺漏項目不透明，容易在資料或 LINE 尚未完成時誤啟用。
- 優先級：P0
- 階段：V1.x
- 狀態：未排程
- 完成標準：清單可驗證基本資料、房型與價格、FAQ、LINE 連線、測試訊息及正式啟用，並清楚顯示未完成項目。

## P1／V1.x

### 7. Onboarding 標題與視覺層級改善

- 解決的痛點：重要題目與次要欄位的視覺層級不足，業者容易漏填或誤判。
- 優先級：P1
- 階段：V1.x
- 狀態：未排程
- 完成標準：「入住方式」「提早入住規則」「延後退房規則」等題目明顯放大加粗，「狀態」與「補充內容」維持次要層級。

### 8. Onboarding 分步驟

- 解決的痛點：單一超長表單造成填寫疲勞、進度不明與資料遺失風險。
- 優先級：P1
- 階段：V1.x
- 狀態：未排程
- 完成標準：每頁只處理一類資料，具備進度、自動儲存與清楚範例，且可安全返回續填。

### 9. 新業者導入 SOP 簡化

- 解決的痛點：現行導入包含過多技術詞彙與人工判斷，耗時且容易出錯。
- 優先級：P1
- 階段：V1.x
- 狀態：未排程
- 完成標準：業者可在 30～60 分鐘內完成填寫，平台可在 10～15 分鐘內完成審核，且流程不要求理解技術詞彙。

### 10. 平台管理者核准預覽

- 解決的痛點：核准前難以確認目標 property、資料變更範圍與 inventory mapping。
- 優先級：P1
- 階段：V1.x
- 狀態：未排程
- 完成標準：核准前顯示目標 property、將更新與不更新的資料、room／bundle mapping 並要求二次確認；既有旅宿遷移維持特殊流程。

### 11. Google Sheet／Apps Script 舊系統遷移與封存 SOP

- 解決的痛點：舊系統資料遷移缺乏一致驗證、回退與停止寫入規則，容易形成長期雙寫。
- 優先級：P1
- 階段：V1.x
- 狀態：未排程
- 完成標準：完成舊正式資料盤點、一次性匯入 PostgreSQL、筆數與內容驗證、舊系統寫入凍結及短期回退，並禁止長期雙寫。

### 12. LINE 正式切換與回退 SOP

- 解決的痛點：正式 Webhook 切換缺少一致的驗證、漸進測試與快速回退流程。
- 優先級：P1
- 階段：V1.x
- 狀態：未排程
- 完成標準：SOP 包含舊 Webhook 備份、新 Webhook 驗證、小範圍測試與重大錯誤立即回退，且不要求業者操作 Render。

## P2／V2

### 13. 平台內部產品待辦頁

- 解決的痛點：未來多位平台管理者可能缺少共同查看與維護產品待辦的介面。
- 優先級：P2
- 階段：V2
- 狀態：未排程
- 完成標準：僅在出現多位平台管理者的實際需求後建立；此前持續以 repo 文件與 GitHub Issues 維護。
