# Phase 1 isolated candidate: scoped public replies

User-approved behavior: registered facts remain visible; genuine missing guest input is clarified; unresolved internal outcomes retain their type/provenance but produce no independent guest failure text. Human notice requires request responsibility evidence and is exactly「請稍後，將盡快回覆您。」. Unknown is never a negative fact or automatic human responsibility.

Changes at existing boundaries:

- C07 required clarification remains a task render obligation even when a public availability reference exists. The existing undated-price reference-only path remains unchanged.
- The existing FinalDecision issues property/turn-scoped public actions only after branded claim validation. The original reason, internal action, execution summary and terminal provenance remain available. Existing rendering and actual-byte validation consume these actions; the validation/rebuild/safety path is retained.
- Direct property-wide registered catalog answers carry their existing source scope. An unregistered qualified condition remains Unknown, while a separately proven general policy can be rendered with an explicit general-policy label. Aggregated bundle notes are not promoted into property-wide facts. A separately answered base question owns its facts once.
- The existing Resolver exposes its selected candidate products. Complete registered rates may answer a price request even if availability is closed or formally Unknown, with a registered-rate label. This does not assert bookability or known quantity fulfillment. Technical dependency errors remain technical errors.
- Understanding guidance makes compact compound applicability requests explicit and uses the temporal source event, property timezone and existing ISO-week convention as the sole relative-time basis. No new parser, source predicate, correction call or persisted field is introduced.

Unchanged authorities: OpenAI Understanding; C03/C04/C05 and controlled correction; State/lifecycle; canonical temporal interval comparison; Resolver/PostgreSQL facts; single FinalDecision/FinalResponse; LINE delivery validation. No catalog entry or max=100 change, SQL DDL, persisted State/schema change, or production-data write.

Test expectation classification:

- Old public Unknown/processing prose assertions are superseded by the user-approved public Contract. The tests still assert internal Unknown, provenance, technical-vs-unknown distinction, safety failure, and byte validity. Silent responses are not asserted to possess a delivery seal.
- Old price-before-availability gating assertions are replaced with registered-rate outcomes while preserving inventory availability, source, capacity, quantity, and non-bookability assertions.
- Two existing fixed-clock Context fixtures now pass their already-fixed clock to the provider validator; expiry rules and expectations are unchanged.
- New permanent regressions cover required clarification, scoped public replies/forbidden guest bytes, and independent registered rates. They are appended to the existing phase1-boundaries script. No gate is removed or weakened.
- The fixed natural-language evaluation set is tests/fixtures/phase1-real-eval.json. Saved user observations, fresh REAL-provider replays, and synthetic/recorded tests are separate evidence classes; none is REAL LINE delivery.

Boundary limits: absent room-composition data cannot yield a room count; missing formal inventory or policy conditions cannot become invented facts or permissions. Exact unavailable historical events/SQL rows are not reconstructed from current data. REAL failure-terminal remains NOT_PROVEN. Deployment and user LINE acceptance require separate evidence.
